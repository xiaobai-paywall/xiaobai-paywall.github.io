# 商业变现

两个功能，界面和交互与「小白收息」一致，左侧导航切换（手机上是底部 Tab）：

- **收集素材**：订阅页截图的图库，上传、分类、浏览、搜索。
- **扫描机会**：每天扫描 App Store 分类榜单，找出上线不久、畅销榜远高于免费榜的高价订阅新品。

**打开**：双击 `订阅页图库.html`（推荐 Chrome 或 Edge）。网址末尾 `#/collect` 是收集素材，`#/scan` 是扫描机会，刷新后停留在当前功能。

## 扫描机会

**看什么**：顶部四个数字是今日候选数、7 日上升数、最热内购中位数、90 天内上线数。下面可以按上线时长、最热内购价格、分类筛选，点表头排序。点任意一行打开详情：为什么值得看、30 日排名走势（畅销榜和免费榜）、完整内购价格表（标出周、月、年订阅），以及 App Store 和七麦数据的链接。

**筛选规则**（在 `扫描机会/config.toml` 里改）：上线不超过 540 天（约 18 个月），排除大厂开发者，并且同时满足：

- **有下载量**：进本分类免费榜前 100，估算日下载 ≥ 1000。
- **有付费**：进本分类畅销榜前 100，变现倍数 ≥ 0.25，最热内购 ≥ $19.99 或最贵内购 ≥ $39.99。

**下载量怎么估算**：分类名次不能直接比，同样第 22 名，在「参考」里日下载约 1400，在「娱乐」里是它的好几倍。所以每天额外抓「全部应用」总榜，用同时出现在分类榜和总榜上的应用，拟合出每个分类「分类名次 → 总榜等效名次」的换算关系；再用七麦等平台的真实日下载样本，把等效名次换算成日下载。变现倍数 = 下载的等效名次 ÷ 收入的等效名次，大于 1 说明收入在全部应用里排得比下载更靠前。

估算只是量级参考，**样本越多越准**：在七麦看到某个应用的「昨日下载数」，就加到 `config.toml` 的 `[calibration] anchors` 里（填 App ID、日下载、日期），2 个以上样本会自动拟合换算斜率。目前只有 FoilSnap 一个样本。

**海外表现**：美区筛出候选后，再查它们在其他国家做得怎么样（`config.toml` 的 `[intl]`）。

- **是否上架、当地评分数**：全球 175 个 App Store 国家都查。苹果的评分按国家分开统计，当地评分数大致反映当地用户多少。
- **当地榜单名次**：53 个重点国家（分四组：高付费、中东、新兴市场、南欧东欧）都抓「全部应用」总榜；权重 ≥ 2 的约 30 个国家再抓候选所在分类的免费榜和畅销榜。
- **海外热度** = Σ 市场权重（1–5）× 档位（进总榜畅销 3，进分类畅销或总榜免费 2，只进分类免费 1），小国家进榜不会被当成和大国一样重要。海外只看名次和评分数，不估下载量（下载换算是用美区样本校准的，换到别的国家不准）。
- 列表的「海外」列显示表现最好的 3 个国家，可以按「海外进榜」筛选、按「海外热度」排序；详情里有每个国家的明细和没上架的重点国家。
- 约 1200 次请求，8 个并发约 6 分钟；最多跑 15 分钟，到点或连续失败（被苹果限流）就停，已抓到的照常发布。只存候选应用的海外数据，数据库每天只多几百 KB。国家和权重在 `[intl.markets]` 里改。

**每天自动跑（在 GitHub 云端，不需要开电脑）**：`.github/workflows/scan.yml` 每天北京时间 9:30 左右（GitHub 高峰期可能延后几十分钟）在 GitHub 的服务器上扫描，抓取 24 个应用分类（与七麦一致，不含游戏）的免费榜和畅销榜（各前 100 名）、应用详情和内购价格，再查候选的海外表现，把结果 `扫描机会/数据/latest.js` 提交到仓库，网页随之更新。约 10 分钟，公开仓库免费。

- **手动跑一次**：GitHub 仓库 → Actions → 扫描机会 → Run workflow，或终端运行 `gh workflow run scan.yml`。
- **看运行记录**：GitHub 仓库 → Actions；失败时 GitHub 会发邮件。
- **停用**：Actions → 扫描机会 → 右上角 ··· → Disable workflow。
- **排名历史**：数据库 `scout.db` 不进 Git（每天一份会越积越大），存在 Release「scan-data」的附件里，每天下载、更新、覆盖，**只保留最近 30 天**，大小稳定在 15MB 左右。不要删除这个 Release，删了历史走势会从零开始。苹果不提供历史榜单，7 日变化和走势图只能靠每天扫描积累。
- **飞书推送**：仓库 Settings → Secrets and variables → Actions，添加 `FEISHU_WEBHOOK`（和可选的 `FEISHU_SECRET`）。

**在本机跑**（调试用，平时不需要）：`python3 ~/Documents/cursor/商业变现/扫描机会/scout.py`。本机数据库 `扫描机会/数据/scout.db` 和云端的是两份，想用云端的历史先运行 `gh release download scan-data -p scout.db -D 扫描机会/数据 --clobber`。注意本机跑完也会自动推送 `latest.js`。

**飞书推送（本机跑时）**：飞书群 → 设置 → 群机器人 → 添加自定义机器人。在 `扫描机会/` 下新建 `config.local.toml`（不进 Git，因为仓库是公开的），写入：

```toml
[feishu]
webhook = "https://open.feishu.cn/open-apis/bot/v2/hook/..."
secret = ""   # 机器人开启签名校验时填写
```

每次扫描完推送前 10 名，底部带网页版「扫描机会」的链接。

**发布到网页版**：`config.toml` 里 `[publish] auto_push = true`，扫描完自动提交并推送 `latest.js`。注意网页是公开的。`同步到GitHub.command` 推送前会先拉取云端每天的提交，不会冲突。

**数据说明**：排名和内购价格来自 App Store 公开榜单和页面，是真实数据；苹果不公开下载量和收入，候选产品请到 AppMagic、七麦核对。

## 收集素材（订阅页图库）

截图瀑布流 + 自定义标签 + 组合筛选。

**上传**：点「上传图片」直接选文件，或把图片拖进页面、⌘V 粘贴截图，不需要任何授权。支持 PNG、JPG、WebP、GIF，不支持视频。上传时会自动无损压缩：尺寸不变，PNG 截图转成无损 WebP（体积约减半，像素和原图完全一致，iPhone 广色域颜色也保留）；压缩后会逐像素校验，有任何差异或省不到 10% 就保留原图。JPG、GIF 保留原样。每张图单独成一张卡片；打开后可以追加图片。

**批量导入（推荐，不会重复上传）**：把截图丢进 `待整理/`，点「从「待整理」导入」，第一次选择 `商业变现/待整理` 并允许编辑。会导入里面所有图片，每张确认已写进素材文件夹后就删除原图，下次只会导入新放进去的。需要先连接素材文件夹（见下方「存储」）；非图片文件不会动。

**打标签**：上传后会弹出「快速打标签」，填来源、点几个标签，会同时打到这次上传的所有文件上；不想打可以直接点「完成」。之后打开单张图片也能改。

**搜索**：顶部搜索框（按 `/` 快速聚焦），能搜标题、来源、标签、备注、文件名，多个关键词用空格隔开。

**放大浏览**：点卡片进入大图模式，右侧显示标签和备注。点图片放大 2 倍看细节；← → 切换图片，↑ ↓ 切换同一张里的多张图，E 编辑，Esc 关闭。可以「复制图片」或「下载原文件」。

**对比**：卡片左上角勾选（或按住 ⌘ 点卡片），底部出现操作栏：「并排对比」把几张图和标签放在一起看；「批量打标签」一次给选中的图片打标签。

**存储**：素材默认保存在本机浏览器里（和「小白收息」一样），清除浏览器数据会丢失。想在硬盘上也留一份，点右上角「备份到素材文件夹（可选）」，选择 `订阅页图库/素材` 并允许编辑，之后会自动同步，已有的素材也会补备份过去。

**管理标签**：右上角「管理标签」。分组和标签都由你自己定义，程序不预置任何文案：「＋ 新建分组」建分类（可选），在分组里「＋ 添加」建标签，点名字改名，× 删除。不建分组也行，直接输入标签会放进「未分组」。旧版本预置的那 5 组标签（品类、平台、页面类型、价格方案、亮点）会在打开时自动清掉，你自己加过的标签保留。

**筛选**：左侧点标签。同一分组内多选是「或」，不同分组之间是「且」。

│   └── 素材/              # 所有上传的截图 + data.js（方案和标签数据）
├── 扫描机会/
│   ├── scout.py           # 扫描脚本
│   ├── config.toml        # 分类、筛选条件、飞书、自动推送
│   ├── assets/            # 扫描机会的样式和脚本

备份或换电脑：复制整个 `商业变现` 文件夹即可。

## 同步到 GitHub

本文件夹是独立的 Git 仓库，对应 GitHub 组织 `xiaobai-paywall` 下的公开仓库 `xiaobai-paywall.github.io`，推送后自动发布到 <https://xiaobai-paywall.github.io>（网页版只读：只显示已推送的素材，网页上新上传的图只存在那个浏览器里）。

注意：仓库和网页都是公开的，推送上去的截图和标签任何人都能看到。

1. 先在图库里点「备份到素材文件夹」，图片才会写进 `素材/`，Git 才能看到。
2. 双击 `同步到GitHub.command`，自动提交并推送，约 1 分钟后网页更新。也可以在 Cursor 里说「提交并推送图库」。

网页版（xiaobai-paywall.github.io）没有服务器，在网页上传的图只存在那个浏览器里；要出现在网页上，必须在本地上传后同步。

**仓库瘦身**：Git 会保留已删除图片的历史，仓库只增不减。觉得仓库太大（比如超过 500MB）时，在 Cursor 里说「给仓库瘦身」，或者执行下面的命令，把历史压成一个提交并覆盖推送，已删除的图会被彻底清掉：

```bash
cd ~/Documents/cursor/商业变现
git checkout --orphan slim && git add -A && git commit -m "瘦身：保留当前素材" \
  && git branch -D main && git branch -m main && git push -f origin main \
  && git gc --prune=now
```

换电脑：`gh repo clone xiaobai-paywall/xiaobai-paywall.github.io 商业变现`，双击 `订阅页图库.html` 就能看到全部方案；之后想继续同步，再点一次「备份到素材文件夹」选择 `订阅页图库/素材`。
