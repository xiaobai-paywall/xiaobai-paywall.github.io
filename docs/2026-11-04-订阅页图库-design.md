# 订阅页图库（Paywall Gallery）设计文档

日期：2026-11-04
状态：已确认，待实现

## 1. 背景与目标

为 iOS / Google Play 新产品快速找到合适的订阅方案和 A/B 策略，需要一个**以截图为主**的订阅方案档案库与筛选库。

形态参考 Pinterest / Mobbin：截图瀑布流 + 自定义标签 + 组合筛选。

目标：
- 收录成本低：拖入截图即可入库。
- 标签完全自定义：标签分组和标签都可增删改。
- 筛选快：多标签组合筛选，快速找出候选方案。
- AI 可读写：数据为本地 JSON，Cursor 中的 AI 可直接批量识别、打标签、对比方案。

非目标（第一版不做）：账号登录、多人协作、云端存储、自动抓取竞品。

## 2. 使用场景

1. 看到好的订阅页 → 截图 → 拖进网页（或丢进 `待整理/` 让 AI 处理）。
2. 打开截图详情 → 点选标签、填来源/备注/状态。
3. 新产品立项 → 左侧勾选标签组合（如「AI」+「带试用」+「年订阅」）→ 浏览候选 → 挑方案进入 A/B 测试。
4. 测试结束 → 把状态改为「胜出 / 淘汰」，填写实测数据，沉淀经验。

## 3. 功能设计

### 3.1 页面布局

- **顶部栏**：标题、搜索框（匹配来源 / 备注 / 标题）、「上传截图」按钮、「管理标签」按钮、结果计数。
- **左侧筛选栏**：按标签分组折叠展示，每个标签显示使用次数；顶部有「清空筛选」；另有「状态」筛选。
- **中间瀑布流**：卡片显示封面图、来源、前若干个标签、状态角标。
- **右侧详情抽屉**：点击卡片打开。

### 3.2 方案（条目）

一个条目 = 一个订阅方案，可包含多张截图（如订阅页 + 挽留页）。

字段：
| 字段 | 说明 |
|---|---|
| id | 自动生成，如 `P0001` |
| title | 标题，可选，如「Calm 年订阅试用页」 |
| source | 来源 App 名称 |
| images | 截图文件名数组，第一张为封面 |
| tags | 标签 id 数组 |
| status | 储备 / 待测 / 测试中 / 胜出 / 淘汰 |
| note | 备注（亮点、价格细节等） |
| metrics | 实测数据，自由文本 |
| createdAt / updatedAt | 时间戳 |

平台、地区、品类等用标签表达，不单独设字段，保证筛选统一。

### 3.3 自定义标签

两层结构：**标签分组 → 标签**。

- 分组：新增、改名、删除（需确认，组内标签一并删除并从条目上移除）。颜色按分组自动分配。
- 标签：新增、改名、删除（从所有条目上移除）。
- 详情抽屉中可输入新标签名直接创建，并选择所属分组。
- 每个标签显示被引用次数。

预置分组（可随意修改，刻意保持精简）：
- 品类：工具、健康、AI、游戏、内容
- 平台：iOS、GP
- 页面类型：单页、多步引导、试用开关、限时折扣、挽留页
- 价格方案：周、月、年、终身、免费试用
- 亮点：锚点对比、按周折算、首期优惠、弱化关闭

UI 风格与 `探索/金融`（小白收息）保持一致：深色海军蓝底、分组强调色、金色标题、绿色主按钮。

### 3.4 筛选规则

- 同一分组内多选为 **OR**，不同分组之间为 **AND**。
- 状态筛选与标签筛选为 AND。
- 搜索框与上述条件为 AND。

### 3.5 上传

- 支持点击选择和拖拽到页面，支持多张。
- 默认每张图生成一个新条目；在详情抽屉中可给已有条目追加截图。
- 图片保存到 `images/`，文件名为 `时间戳-随机串.扩展名`。

## 4. 技术方案

> 2026-11-05 更新：改为纯 HTML 入口（与 `探索/金融` 同格式），不再需要 Node 服务。
> - 入口 `商业变现/订阅页图库.html` → `订阅页图库/index.html`，双击即开。
> - 截图和数据存放在 `订阅页图库/素材/`：通过 File System Access API（Chrome / Edge）授权该文件夹后写入；文件夹句柄存 IndexedDB，下次打开免选择。
> - 数据文件为 `素材/data.js`（`window.__GALLERY__ = {...}`），页面用 `<script>` 读取，未授权时也能浏览；localStorage 作为缓存，按 `savedAt` 取较新的一份。
> - 图片用相对路径 `素材/xxx.png` 显示。
>
> 以下为初版（Node 服务）方案，仅作记录。

- **服务端**：Node.js（本机 v24），仅用内置模块（`http`、`fs`、`path`、`crypto`），零依赖。
- **前端**：原生 HTML + CSS + JS，单页，CSS columns 实现瀑布流。
- **存储**：
  - `data.json`：`{ groups: [...], tags: [...], items: [...] }`
  - `images/`：截图原图
  - 写入采用「写临时文件 → rename」保证不损坏。
- **启动**：`node server.js`，默认 `http://localhost:5173`，或双击 `启动图库.command`。
- **仅监听 127.0.0.1**，不对外暴露。

### API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/data` | 获取全部数据 |
| POST | `/api/upload` | 上传图片（原始二进制，文件名放 header），返回文件名 |
| POST | `/api/items` | 新建条目 |
| PUT | `/api/items/:id` | 更新条目 |
| DELETE | `/api/items/:id` | 删除条目（同时删除未被引用的图片） |
| POST/PUT/DELETE | `/api/groups[/:id]` | 分组增改删 |
| POST/PUT/DELETE | `/api/tags[/:id]` | 标签增改删 |
| GET | `/images/*` | 图片静态访问 |

## 6. 错误处理

- 非图片文件拒绝上传并提示。
- `data.json` 不存在时用预置标签初始化；解析失败时备份为 `data.broken-时间戳.json` 后重建并提示。
- 前端请求失败给出 toast 提示，不静默。

## 7. 验证

- 启动服务，上传 2–3 张图，打标签，组合筛选结果正确。
- 新建 / 重命名 / 删除标签和分组后，条目上的标签同步更新。
- 重启服务后数据保留。
